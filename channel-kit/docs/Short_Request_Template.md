# Short request template (ServiceNow Simplified)

Copy this, fill what you have, paste it in chat. Only the first 3 items are required. Rough notes are fine.

```
1. TOPIC: one line. What does the viewer learn?
   e.g. "Copy a user's manager into a catalog variable without a script"

2. PROBLEM → FIX → GOTCHA:
   Problem: what goes wrong / what people do badly
   Fix:     the steps or the code
   Gotcha:  the mistake that bites (this becomes the hook or the twist)

3. REAL DETAILS (exactly as on your instance):
   - Code (paste it, don't retype from memory)
   - Table / field / variable names
   - Menu path (e.g. System Definition > Script Includes)
   - Release you tested on (e.g. Zurich, Yokohama) and: tested on PDI? yes/no

4. SOURCE (optional): episode transcript, notes, or a screenshot (blur client names, URLs, user names)

5. RELATED VIDEO (optional): the long video this Short points to (goes in the Related video field)

6. VOICE (optional): voice 9 (default) or my own recording

7. COUNT (optional): 1 Short, or "split if needed"
```

## Notes
- **One idea per Short.** 25–45 s ≈ 70–110 spoken words. Bigger topics get split into A/B Shorts or go into a long video.
- **Several topics in one message are fine.** Claude picks the ones that make good Shorts and says which don't.
- **Screenshots help accuracy**, but on-screen UI is redrawn in the PPT style and labelled "illustrative". Raw screenshots
  are never shown, so client data can't leak.
- **Screen recordings** (1080p or higher) can be cut in for real UI moments; say if you want that.
- Claude can't open YouTube links from the container. Paste the transcript instead (YouTube → "Show transcript" → copy).
- Anything you're unsure about, mark it with `?`. It gets checked against ServiceNow docs/community or flagged back to you
  before it goes on screen.
